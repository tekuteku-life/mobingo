# Pixelの振動無反応と確認機能の検証

## 対象

基準はmainの03cef18である。製品版は1.4.2であり、対象はR-24、E-20、I-19、U-12である。本変更は振動の受付結果と実機確認のための機能であり、Pixelの振動無反応を解消したとする修正ではない。

Pixel 9aではアプリの振動設定オン・API対応・requestedを確認したが、物理振動が出ないという利用者報告がある。インストール済みPWA、通常タブ、Chrome公式振動サンプルでも再現し、消音・集中モードに加えて、2026年11月3日には通常・強力な省電力モードの両方オフも確認済みである。追加回答ではメディア以外のハプティクスをオフにしている。

## 実装

振動APIの共通境界で戻り値false、非対応、例外、要求受付を区別し、通常操作の直近結果も保持する。アプリ情報に設定を尊重した200msの確認操作と、版・ブラウザー・起動形態・利用者操作・対応と結果をコピーできる欄を設ける。ゲーム情報を参照・自動送信しない。閉鎖後の古いボタンは無効である。

既に配信された版からの更新を区別するため、製品版とWorkerキャッシュを1.4.2へ揃える。mainの音声実装には差分を持たない。利用者の指示により、作業ブランチの履歴は振動の設計・試験・実装へ整理する。

## 調査結果

Chromiumの表示・利用者操作チェックと非同期のネイティブ要求、AndroidのVIBRATE権限・用途補正・用途別強度・前面判定・AppOpsを確認した。短いパルスはTOUCH用途へ補正される経路があるため、UNKNOWN用途のメディア強度だけを理由にしない。省電力は抑制条件の一つだが、利用者がオフを確認しているため、既知の原因とは扱わない。

メディア以外がオフという回答から、短い振動のTOUCH分類を調べた。同日の実機確認で、メディア振動の切替では変化せず、タッチフィードバックの切替で振動が変わるとの回答を得た。今回の無反応は操作用の振動が端末設定で抑制されていたことに対応し、短い振動とタッチ設定の関係は実機報告で確認済みである。

一次ソースと再発時の観測手順は[切り分け手順](../haptics_troubleshooting.md)へ記載した。Web APIにはMEDIA用途へ切り替える引数がない。今回の結論は利用者による設定切替と物理振動の報告に基づき、requestedだけから判断したものではない。OSの内部status採取と全ゲーム操作での実出力確認は未実施である。

## 検証

`npm run lint`は終了コード0である。重点試験は単体1件・UI9件の10/10が合格した。`npm run test:coverage`は終了コード0、単体・結合・システム95/95、UI160/160、計255/255が合格した。ソース不変検査を含む23対象のLine/Branchはすべて97%以上であり、最小Line98.36%、最小Branch97.68%である。haptics.jsとlicense-modal.jsはLine/Branchとも100%である。Node V8とChromium CDPの範囲を位置で合算した測定である。

mainとaudio.jsのバイト一致、音声比較ファイルの削除、依存lockの差分がアプリの版だけであることを確認した。独立レビューは未実施である。これらの合格を実機の振動成功や原因確定とは扱わない。
