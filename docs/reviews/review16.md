# Pixelの音声・振動無反応に対する切り分け記録

## 対象と確認できた事実

確認日は2026年11月1日である。基準はmainの`03cef18`、作業ブランチは`fix/device-feedback-status`、確認機能追加版は1.4.1である。対象はR-24、E-20、I-19、U-12である。

Pixel 9aのインストール済みPWAで音声・ハプティクスがともに効かないという利用者報告を受けた。公開GitHub Pagesの版定数は1.4.0であり、audio.js、haptics.js、app.js、sw.jsの配信内容がローカル1.4.0とSHA-256で一致することを読み取り確認した。利用者から「最新版、アプリ設定のOFF/ONを両方試しても無反応、メディア音量とハプティクスは最大」との回答を得た。数値としての実行版と確認情報、通常のChromeタブでの再現は確認待ちである。単純な音量不足・アプリ設定オフだけが原因とは扱わない。

その後、利用者から「通常のChromeタブでも音・振動が両方出ない」「消音・サイレント・おやすみ時間などのモードもすべてオフでも再現する」と回答を得た。通常タブでの再現は確認済みとし、PWA専用の問題や単純な消音設定に限定しない。数値の版と、実機でのAPI受付結果は引き続き未確認である。

公開版を再確認した時点でも1.4.0であり、作業ブランチの1.4.1の確認UIはまだ実機で利用できない。pushまでの許可とmain反映・本番配信は区別し、利用者が公開を承認してから確認UIを配信する。

ADB接続済みの端末は存在せず、物理出力を直接再現する手段はない。既存の実Web Audio波形試験と振動APIスタブはPixelのスピーカー・モーターの動作を証明していなかった。今回は端末症状の解消を断定せず、ソフトウェア側で隠れていた失敗結果を観測可能にする。

## 是正内容

通常の音声再開の拒否・例外名を保持し、旧contextの遅延完了で現在の結果を上書きしない。確認音の試験は利用者操作内でresumeを要求し、解決してrunningとなった後だけビープ音を生成する。2秒の期限、閉鎖、ミュート化、context差替えで中止し、遅れて確認音を鳴らさない。

振動は共通境界でAPIの戻り値false・非対応・例外・要求受付を分類する。確認ボタンは設定を尊重して200msを要求し、trueでも実際に振動したとは表示しない。通常操作の直近要求結果も確認できる。

情報画面の確認情報には版、ブラウザー、起動形態、secure context、表示状態、利用者操作、音声状態・エラー名と振動設定・直近結果を含める。ゲームIDや個人名を参照せず、端末外へ自動送信しない。読み取り専用欄の選択・contextmenuを有効にする。

事前の重点カバレッジはaudio.js Line100%・Branch99.19%、haptics.jsは両方100%である。情報画面の更新・閉鎖の既存分岐は全体実行で確認する。全体のゲートと重点測定を混同しない。

実装者による確認では、成功表示の意味、設定保持、二重発音・遅延応答、旧contextの結果、情報の非HTML描画・非送信、確認欄のコピー、低い横画面の到達を点検した。独立サブエージェントレビューは未実施である。

## 未解決の実機境界

Pixelにおける無反応の根本原因と実出力は未確認である。今回の追加は切り分けと失敗通知であり、端末症状の解消を証明する修正とはしない。

- 音声の拒否・開始待ちなら、ブラウザーの再生制約と実行状態を調べる。
- 再生要求済みでも聞こえない場合は、メディア音量・出力先・ブラウザー設定・端末の再生経路を切り分ける。
- 振動falseはブラウザーの拒否であり、trueでもOS設定・機器側で無効となる場合がある。API非対応と区別する。

根拠は[MDNの振動API説明](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)、[Google Pixelの音・振動設定](https://support.google.com/pixelphone/answer/16785703?hl=ja)、[Chromiumの自動再生方針](https://www.chromium.org/audio-video/autoplay/)である。Webから端末設定を強制変更しない。
