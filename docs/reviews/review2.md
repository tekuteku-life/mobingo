# テスト設計・実装レビュー記録

対象は`test/`、`scripts/`、型検査設定、npmコマンドと要求・設計の対応である。独立サブエージェント`test_review`が実施した。

## 指摘と対応

初回は再読込の旧DOM待機、確認取消、非同期離脱、操作時間境界、モードA集計、QR入力契約、抽選全体、v1互換性ベクトルの不足が指摘された。document世代待機、承認/取消指定、遅延KDF・カメラ・タイマーの試験、独立した集計、QR入力、自然抽選・75手停止、基準`061f8af`で採取した固定ベクトルを追加した。

再レビューでは599/600ms境界、実画面のRAF・ResizeObserver解放、QRの処理待機が不足とされた。600ms専用の制御時計、実画面の資源追跡、decoderでの処理済みペイロード記録を追加した。

修正後の独立再レビュー応答は`PASS`である。製品はこの工程では未修正であり、赤試験の合格・最終受入とは別判定である。

## 実行環境と分類

Node v24.19.0とローカルChromiumを使用する。通常サンドボックスのHTTP listenはEPERMとなったため、許可された制約外実行で変更なしに再実行した。QR入力試験は光学認識を代替し、復号後の入力境界を検証する。QR生成物の読取は実jsQRで別途検証する。

修正前の実測として、単体・結合・システムは53件中48件合格、5件失敗であった。その後にCanvas解放等のテストを追加したため、この件数は最終件数ではない。失敗は開催者復元、保存型検証、他アプリキャッシュ削除、抽選の未定義関数参照を含む。UIはキャンセル・移動、遅延完了、ID保持、QR形式等で失敗した。テスト期待値の妥当性と製品不具合を切り分けた上でPhase 4へ進む。
