# モバイルUIテストレビュー

対象は`test/ui/mobile-layout.test.js`、`test/helpers/layout.js`およびbrowser補助のmobile/touch・向き変更・実タッチ入力である。独立サブエージェント`test_review`がレビューした。

## 指摘と対応

1. 表示だけではタッチ操作不能を検出できない。実タッチでセルを開封し、スライダーで1球抽選して保存・表示まで確認する試験を追加した。
2. FREEのみ・0手では状態リセットを検出できない。開封済み0,0と実抽選1手を用い、向き変更後の保存値、カード数字、開封表示、最新球、投影手番を照合した。
3. 結果や順位の一部が隠れていても合格する。カメラ領域、照合メッセージ、25マス、順位3件へ実touchスクロールで到達するassertを追加した。
4. 投影開閉の資源解放が不足している。3回開閉し、監視数、旧Canvas、RAFを検証する試験を追加した。

修正後の独立再レビュー結果は`PASS`である。viewportとすべてのクリップ祖先、hit-test、数字の横幅収容、樽の最小寸法、右上の操作位置を検証する。scrollIntoViewやscrollTop代入は到達操作として使用しない。

7サイズの3シナリオと連続向き変更の計22ケースを追加した。既存4層テストに加えて実行する。カメラ権限失敗は試験用であり、光学性能は対象外である。実OSキーボードや端末固有のブラウザバー・ノッチ形状はエミュレーションだけで確認済みとはしない。

## 試験補助と追加境界の再レビュー

固定距離のswipeが対象を上下へ行き過ぎて往復する試験側不具合を、scrollTopと矩形で診断した。実矩形のはみ出し量とタッチ開始の余裕から移動量を決める方式へ改めた。実touchイベントだけを使用する点は維持する。

横向き2列表示で844×390のセットアップが収まるようになったため、既存wheel試験はスクロールが必要な844×220へ移し、wheel座標もviewport内へ変更した。通常の844×390は新しいmobile全画面試験で確認する。縦投影heroの45%上限と、PWA orientation:anyの結合試験も追加した。

これらの追加・修正も独立サブエージェント`test_review`が再レビューし、最終応答は`PASS`である。

## スライダー縦panの追加回帰

最初の全体実行は単体・結合・システム63/63、UI66/67であり、640×280の操作到達が失敗した。別の640×360でもtrackの縦panがscrollTopを変えず失敗することを確認した。

trackとthumbは独立したページの2ケースで検証する。各操作直前に可視性、hit-test、親のスクロール余地を確認してから縦panし、スクロール増加・手番0・回転なしをassertする。最初のpanが終端に達して次のpanを誤判定する試験上の問題も独立レビューで修正した。追加分の最終テストレビュー応答は`PASS`である。新しいmobile UI試験は計24ケースである。
