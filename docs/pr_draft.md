# プルリクエスト草案

## タイトル

参加者の表示名・QR連携・当選順の追加とPC/タブレットUIの改善

## 背景

PCの縦長セルで復元リングが欠け、iPad縦画面の開催者表示は幅上限によって中央へ縮小していた。参加者のリセット重複とID/リーチの段落ちを修正し、表示名の設定・取得と成立手番による当選順を追加する変更である。

## 変更内容

- 復元リングを固定viewBoxと円の回転へ変更し、縦長・横長セルの短辺内へ収める。
- 開催者の準備・受付・進行画面の幅上限を廃止し、横画面または幅700px以上では操作と出目ボードを左右へ配置する。
- 参加者のID/リーチを1行へ整理し、リセットは表示中1個の小さい補助操作とする。名前入力後も標準横画面の参加ボタンを初期表示内へ収める。
- 表示名は任意32コードポイント、前後空白除去・NFC正規化とする。制御文字・全方向制御文字を拒否し、本文・属性をエスケープしてXSSを防ぐ。参加後に開封を維持して編集できる。
- 名前付きv2 QRを生成し、開催者の受付・照合から名前を取得する。旧QR・生4文字ID・旧保存は受理する。名前のない旧QRは既知の名前を維持する。
- 当選順は最初の有効成立手番順、同手番は同順位1/1/3とする。モードAは登録者と有効照合者、モードBは有効照合者を対象とする。Undo・解禁・再読込・新ゲームへ追従する。
- 生成v1と既存保存キーを維持し、任意フィールドを追加する。製品・SWキャッシュを1.1.0へ同期する。

## 確認内容

PC実mouse長押し、iPad縦横・正方形・超横長、既存スマホ7サイズ、低い横画面の実touch、表示名の長文/不正値/XSS/QR/復元、受付・照合の遅延完了と破棄、独立ライン再生による順位を検証する。要求とassertは[設計テスト監査](design_test_audit.md)、再現失敗と最終実測は[review10](reviews/review10.md)を参照する。

## テスト結果

受入コマンドは`npm run lint`と`npm run test:coverage`である。`npm run lint`はエラー0件、`npm run test:coverage`は終了コード0である。単体47・結合21・システム4・UI92、計164/164合格である。自作20ファイルすべてのLine/Branchが97%以上で、最小Line99.18%・Branch97.56%である。ファイル別実測はreview10に記録した。

## レビュー結果

設計・テスト・最終コードを独立サブエージェントでレビューする。方向制御文字漏れ・モードB順位混入・参加ボタンの回帰は、設計または失敗テストへ戻して是正する。最終レビューは設計・テスト・コードとも`PASS`、未解決指摘0件である。review10に記録した。

新QRの読取には開催者側アプリの更新が必要である。実機カメラ、OSキーボード/ブラウザUI、安全領域、実振動/音声/Wake Lock、外部モニター、本番HTTPSと既存PWA更新はローカル自動試験の範囲外である。
