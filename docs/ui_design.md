# UI設計書

## 1. 共通レイアウト（U-01／R-01、R-15）

ダーク背景と共通ヘッダーを持つ。ヘッダーはMobingoロゴ、開催者/参加者バッジ、音声切替、役割選択へ戻るボタン、情報ボタンである。ロゴと役割変更は確認ダイアログを経由する。情報モーダルは閉じるボタンまたは背景で終了する。

R-22の振動切替は音声切替の隣に置き、押下状態とラベルでオン・オフを示す。参加者の縦横両方のQRボタンは「参加登録・照合用QR」とし、再作成ボタンを上罫線と余白を持つ独立領域に置く。リセットは通常2回、現在のビンゴまたは開催終了条件を満たす場合は1回確認する。球表示中のタップは終了のみ、成立スライドは次球開始まで行い、スクロール位置を維持する。

ヘッダーの役割バッジは折り返さず、幅380px以下では省略する。ロゴと音声・振動・役割変更・情報・外部投影の各操作をヘッダー内に収める。

短い横画面の役割選択・参加者セットアップは紹介と操作の2列構成とする。開催者セットアップも選択肢と開始操作を横へ分け、必要時はコンテナ内を指でスクロールして全操作へ到達できるものとする。カード表示自体のスクロールレス要件とは区別する。

役割選択には`#btn-select-child`と`#btn-select-host`を配置する。音声切替でゲーム状態を失わない。役割変更中に旧画面の演出・カメラを残さない。

## 2. 参加者セットアップ（U-02／R-02、R-04）

`#child-setup-form`に`#child-seed-input`、再生成ボタン、参加ボタンを配置する。IDの補正はinput時、妥当性検査はsubmit時である。有効IDの導出完了後にカードを表示し、連続submitで古い結果を反映しない。

## 3. 参加者カード（U-03／R-04〜06、R-11、R-14）

`#bingo-cells-grid`は5×5の正方形である。各セルに`data-coord`と`data-free`を持たせ、未開封・開封済み・特殊役対象・完成ラインを区別する。中央FREEは操作不能である。

- 未開封を400ms未満でタップすると穴あけ演出後に開封表示する。
- 開封済みの短いタップは無変更、600ms以上の長押しは進捗リング後に復元する。
- 10px以上の移動、pointercancel、捕捉喪失は操作を中止する。
- リーチ1本は黄、2本は赤、3本以上は虹色の枠を用い、待ち数字を補助帯に表示する。
- ビンゴでは成立ラインとBINGO表示、紙吹雪・音声・振動、約700ms後のQR自動表示を行う。復元で未達成へ戻せる。

縦画面はカードIDとリーチを上、特殊役・QR・リセットを下に置く。横画面は右側パネルへ情報と操作を移す。基準試験サイズは320×568、360×640、390×844と各横向き568×320、640×360、844×390である。表示領域が狭まる640×280、連続した縦→横→縦の向き変更も検証する。操作対象がviewport内にあることを実測する。

`#child-qr-modal`には同梱QRCodeで描いたcanvas、4文字ID、上部と下部の閉じる操作を置く。再作成の確認を承認するとカード状態を削除してセットアップへ戻る。

## 4. 開催者セットアップと受付（U-04／R-02、R-09）

`#opt-mode-a`、`#opt-mode-b`、`#host-seed-input`、再生成、`#btn-host-proceed`を表示する。初期選択はモードBである。モード切替でも入力中のIDを保持する。

モードAはvideo、QR枠、登録トースト、手入力フォーム、IDチップ一覧、削除、受付人数、戻る、受付終了を表示する。0人では終了ボタンを無効にする。重複は警告し人数を増やさない。カメラ拒否後も手入力を使用できる。受付から離れるとカメラを停止する。

## 5. 開催者ダッシュボード（U-05／R-07〜09、R-11、R-14）

開催者ヘッダーの右端に高さ44px以上の外部投影ボタンを置く。セットアップ中は無効、ダッシュボードでは有効とし、画面再描画でイベントを重複登録しない。

Canvasの樽と最新球、開催ID・モード・手番、直近最大20球、スライダー、Undo、特殊役解禁、照合、投影、リセット、出目ボードを配置する。横画面または幅700px以上では右側に75球の常設ボードを表示し、展開ボタンを隠す。幅700px未満の縦画面では展開式マトリクスを使用する。

スライダーはpointer捕捉中に進捗を表示し、移動範囲の85%以上で抽選を開始する。pointercancelは成立させない。スライダーとつまみの上でも縦方向のスワイプは親パネルをスクロールし、横方向のドラッグだけで抽選する。ヒントは待機、回転中、球確定を表示する。樽クリックで演出を順にスキップする。75手後は抽選を無効にする。

スマートフォンの樽表示は縦画面で200px以上、横画面で160px以上の短辺を確保する。操作パネルは必要時に内部スクロールできるものとし、樽の拡大によって操作を切り捨てない。

モードAでは総リーチ・ビンゴ成立者IDと次球の予告、逆ビンゴ賞ボタンを追加する。逆ビンゴ賞は出目との一致数が少ない順に上位3件である。特殊役解禁は確認後にカットイン表示してダッシュボードへ戻る。

## 6. 照合・投影（U-06／R-10、R-14、R-16）

`#host-verify-modal`はカメラ/手入力タブ、入力・照合中・結果状態を持つ。結果は有効/未達成、成立手番とパターン、ID、一致数、再現5×5カード、別の参加者を照合するボタンである。タブ切替、閉じる、背景クリックで旧カメラを停止する。閉じた後の照合完了は表示しない。

`#projector-view`は表示可能領域とsafe areaに収め、右上の固定ヘッダーに「操作に戻る」ボタンを置く。通常画面の外部投影ボタンと右端・上端を近づける。スマートフォンのボードはB/I/N/G/Oの5行、各15数字を横に並べ、75数字を見切れなく表示する。縦向きでは上部に樽と最新球、下部に横長のボードを配置する。樽と最新球のパネルは表示高の45%以内とし、過大な縦方向の引き延ばしを避ける。横向きでは左右に配置する。表示中の抽選ボタンは提供せず、開いた時点の状態を表示する。終了時はCanvas監視を破棄する。

## 7. 操作性と未保証境界（U-07／R-14、R-15）

タップ対象は視認可能な大きさを保つ。ページ全体の意図しないスクロール・テキスト選択・コンテキストメニューを抑止し、セットアップ・受付・操作パネルの意図した内部スクロールは許可する。モーダルの長い情報は内部スクロールする。現在のセル・モードカードにはdivベースのpointer操作があり、完全なキーボード操作やスクリーンリーダー対応は保証されていない。これらをアクセシビリティ達成済みとして扱わない。

アプリにプルダウンを追加する場合も、説明文は「ですます」調、短い選択名は名詞ラベルとする。現行画面にはselect要素によるプルダウンは存在しない。


## 8. モバイルUI受入試験（U-08／R-14）

mobile/touchエミュレーションと向き情報を有効にした実Chromiumで、開始、参加者セットアップ、カード、QR、開催者セットアップ、受付、ダッシュボード、照合のカメラ/入力/結果、特殊役、逆ビンゴ賞、情報、投影を縦横で確認する。要素の存在だけでなく、実viewportと祖先クリップの内側、中心のhit-test、文字や数字の行内収容をassertする。

操作の発火には実タッチを使う。内部スクロールの到達性は実touchスワイプで検証し、`scrollIntoView`やDOMの`scrollTop`代入で代用しない。ボード75数字、樽の最小寸法、投影/戻るの右上位置、繰返し開閉後の監視解放、リサイズ後のカード・手番保持もassertする。OSの実キーボード、実端末のブラウザバー・ノッチ形状は別途確認する。

## 9. PC/タブレット・表示名・当選順（U-09／R-17〜19）

復元リングは固定viewBoxとpreserveAspectRatioでセルの短辺内へ収め、円のストロークを含めて欠けないものとする。SVG全体を非正方形のまま回転せず、円だけを回転する。実PCの長押しと、縦長/横長セルを強制した回帰試験を用いる。

参加者ヘッダーはIDとリーチを1行に配置し、上の重複リセットを削除する。表示中のリセットは1個、幅を内容に合わせた高さ36px以下の補助操作とする。QRは40px以上の主要操作を維持する。表示名は作成フォームと参加後の編集モーダルで設定する。カードでは名前を別行へ置き、長い名前は折返し/省略しつつ編集画面で全文を確認できるようにする。リセットで名前も初期化する。名前入力を追加しても高さ320px以上の標準横画面では参加ボタンを初期viewportへ収めるため、参加フォームの余白を縮める。高さ280px等では内部スクロールを許す。

開催者はアスペクト比に依存した28remの最大幅を廃止する。幅700px以上では縦・横・正方形とも操作と75球ボードを2列で使い、狭い縦画面でも横幅いっぱいに操作を広げる。受付・開催者セットアップも広い端末で余白を過大に残さない。参加者のカード最大幅は維持する。

開催者ツールバーへ当選順ボタンを追加し、専用モーダルで順位・表示名/ID・成立手番を表示する。空状態、同順位、長い名前、名前なし、モードBの対象範囲も示す。名前は読取結果、受付一覧、成立者、逆ビンゴ賞でも安全なテキストとして表示する。

検証サイズへ768×1024、820×1180、1024×768、1024×1024、1440×900、1920×1080、2560×720を追加する。スマホ320×568と既存7サイズの回帰を維持し、PCマウスの長押し、ID/リーチの上下位置、リセットの可視個数と大きさ、開催者の横幅利用を実寸でassertする。

## 10. アプリ情報と更新（U-10／R-20、R-21）

既存の情報モーダルに版・更新状態・確認/適用ボタンを置き、共通ヘッダーを増やさない。現在版は常に表示する。更新確認中と適用中は操作を無効にし、他の状態では再試行できる。状態はaria-liveで通知する。最新、準備済み、通信失敗、非対応、入力中断の確認文を丁寧体で表示する。初期状態は「更新はまだ確認していません」である。

スマートフォン縦320×568、横568×320と640×280、iPad相当820×1180で、版・状態・両操作・閉じるまで実touchで到達する。準備済みの長い状態文も折返す。当選順の両モード説明と空状態を実DOMで点検し、実装コードの文章にも常体が残らないよう静的回帰を設ける。

## 11. アプリURLの共有（U-11／R-23）

ヘッダーへ共有アイコンと「アプリのURLを共有」のアクセシブル名を持つボタンを置く。狭い画面ではヘッダー左右の余白と操作間隔を縮め、既存の振動・音声・役割変更・情報・投影も収める。

共有モーダルは、見出し、閉じる、URL欄、コピー、端末共有、QR表示切替、結果通知、QR領域を持つ。URLは長押し選択可能とする。QR領域は生成完了までCanvasを隠し、生成中・失敗を通知する。低い横画面ではモーダル内をタッチでスクロールし、全操作へ到達できる。参加者カードのQRボタンと内容を共用しない。

## 12. 音声・振動の確認（U-12／R-24）

情報画面に「音声・振動の動作確認」を設け、「音を試す」「振動を試す」と個別のaria-live結果を置く。処理中・拒否・待機・設定オフ・非対応・要求受付を明示する。メディア音量・出力先・消音／集中モード・端末の振動設定も確認対象として案内する。

技術的な確認情報は折りたたみ領域に置き、長押しでコピー可能な読み取り専用欄とする。320×568と640×280で確認ボタン、情報欄、閉じるへ実touchで到達できることを検証する。実機の確認結果が得られるまで症状解消とは表示しない。
