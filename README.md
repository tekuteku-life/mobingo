# Mobingo（モビンゴ）

Mobingoは、4文字IDから同じビンゴカードと出目を再現する静的Webアプリである。開催者と参加者の端末間通信を必要とせず、初回取得とキャッシュ完了後はオフラインで進行できる。実行用ビルドと外部CDNは不要である。

モードAは参加者を事前登録し、リーチ・ビンゴ成立者・次球の予告を自動集計する。モードBは事前登録を省略し、当選申告時にQRまたはIDで照合する。4文字IDはカード識別用であり、本人認証や完全な不正防止を保証するものではない。

参加者は任意の表示名を設定・変更でき、名前付きQRで開催者へ渡せる。開催者の当選順は最初の有効成立手番で算出し、同じ手番は同順位とする。モードBでは有効と照合済みのカードだけを一覧へ含める。旧QRと旧保存は引き続き受理するが、新QRの読取には開催者側もアプリ更新が必要である。

音声と振動はヘッダーで個別に切り替える。振動設定は再起動後も保持し、対応端末では穴あけ・復元・樽回し・球排出を振動で通知する。通常回転は2.3秒であり、球表示中のタップは表示終了のみ、成立スライドは次球の回転まで進む。球表示終了時も開催者のスクロール位置を保持する。参加者のQRは参加登録と当選照合に共用する。

ヘッダーの共有ボタンから、アプリURLのコピー・端末の共有メニュー・URL共有用QRコードを選べる。共有対象は現在のアプリURLからqueryとhashを除いたものであり、ゲーム状態を付加しない。端末共有の非対応時もコピーとQRを利用でき、コピーが拒否された場合は表示URLの手動コピーへ案内する。URL共有用QRとカードの参加登録・照合用QRは用途が異なる。

リセットは通常2回確認する。参加者が現在ビンゴしている場合、開催者の75球が排出済みの場合、モードAで非空の登録者全員がビンゴしている場合は1回である。モードBは全参加者を把握できないため全員達成の省略条件を適用しない。

音声・振動が反応しない場合は、盾アイコンのアプリ情報から「音を試す」「振動を試す」を実行する。設定オフ・非対応・開始待ち・拒否・要求受付を区別し、確認情報を端末内に表示する。要求受付は物理出力の成功を保証しないため、実際の音・振動、メディア音量と出力先、消音／集中モードと振動設定を別途確認する。

## 起動と配信

リポジトリのルートを静的HTTPサーバーで配信する。

```sh
python3 -m http.server 8000
```

ブラウザで`http://localhost:8000`を開く。Web CryptoとService Workerを利用するため、本番はHTTPS、ローカルはlocalhostを使用する。`file://`による直接起動をPWA検証の代用にはしない。

GitHub Pagesでは、公開対象ブランチのルートを配信元に指定する。初回はオンラインで資産取得を完了し、その後のオフライン再訪を確認する。ブラウザが保存データを消去した場合の復旧や、モードA受付途中の一覧復元は提供しない。

## バージョンの確認と更新

右上の盾アイコンから「アプリ情報・更新」を開き、実行中の版を確認する。「更新を確認」で通信して準備済みの新版を調べ、「更新して再読み込み」を確認後に実行する。保存済みの参加者・開催者ゲームと役割は保持し、入力途中の内容は再読込で破棄する。受付途中・抽選の回転/球表示中は適用を拒否し、完了後に再試行できる。

更新確認が失敗した場合に最新版とは表示しない。通信がなくても取得済みのアプリでゲームを継続できる。別タブの適用では自動再読込しない。更新UIがない旧版からの初回移行は、全タブとPWA画面を閉じて開き直す。待機中の新版は通常のWorkerライフサイクルで自然に有効化する。

## 開発と検証

検証環境はNode.js 24とChromiumである。依存関係をlockfileから導入する。

```sh
npm ci
npm run lint
npm run test:unit
npm run test:integration
npm run test:system
npm run test:ui
npm run test:coverage
```

`npm test`は単体・結合・システム、`npm run test:all`はこれらとUIを実行する。`npm run check:version`はpackage・lockルート・実行版定数・SWキャッシュの版一致を検査する。`test:coverage`も全4層を実行し、Node V8とChromium CDPの位置情報を合算する。`.coverage/summary.md`と`.coverage/coverage.json`へ結果を出力し、自作`js/`と`sw.js`の各ファイルでLine/Branchのいずれかが97%未満なら失敗する。未ロードの対象も0%として含める。

ブラウザ試験はローカルHTTP待受と子プロセス起動を必要とする。既定のブラウザは`/usr/bin/chromium`であり、別配置では`CHROME_BIN`へ実行ファイルのパスを設定する。各試験は独立したブラウザコンテキストを使用する（別タブ試験は同一コンテキストで共有する）。ヘッドレスのCanvas2DはCPU描画に固定し、実機GPUの動作確認とは分ける。接続・初期化失敗にも期限を設け、終了時は所有するブラウザプロセスとstdioを解放する。

実機カメラの光学性能、実際の音声・振動・Wake Lock、外部モニター、本番HTTPS、既存PWAからの更新は別途確認する。カメラ入力のモックとQR画像の実デコードは異なる検証として記録する。

コードはタブインデント、文書は「である」調、コミットは英語である。設計・テスト・最終実装には独立レビューを必須とする。手順と未達時の扱いは開発プロセス定義書に従う。

## 構成

| 配置 | 内容 |
| --- | --- |
| `index.html`、`css/` | エントリーポイントとレイアウト |
| `js/core/` | ID・表示名・QR、鍵導出、乱数、判定・順位、保存、端末API、ライフサイクル |
| `js/views/`、`js/components/` | 画面、モーダル、スライダー、Canvas |
| `js/lib/` | ローカル同梱のQR生成・読取・紙吹雪ライブラリ |
| `sw.js`、`manifest.json`、`icons/` | PWA配信資産 |
| `test/unit/`、`integration/`、`system/`、`ui/` | 必須の4層テスト |
| `scripts/`、`types/` | 静的検査とカバレッジ、ブラウザ型宣言 |

商標および同梱ライブラリの表記はアプリ内の情報モーダルに掲載する。
